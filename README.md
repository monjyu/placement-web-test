# 配置問題Webテスト（問題1・10問）

研究室のミーティングで共有し、複数の参加者が同じURLから回答できる試作環境です。画面はGitHub Pages、回答保存はGoogleスプレッドシート＋Google Apps Scriptを使用します。

## フォルダ内容

- `index.html`：画面構成
- `style.css`：デザイン
- `app.js`：問題、回答、計時、送信処理
- `config.js`：Google Apps Scriptの送信先URL
- `google-apps-script/Code.gs`：スプレッドシート側の受信処理
- `RESEARCH_PLAN.md`：研究目的、収集データ、難易度調整方針
- `TEST_CHECKLIST.md`：動作確認項目

## 作成・公開手順

### 1. 研究目的と収集データを確認する

`RESEARCH_PLAN.md`を教員と確認します。参加者IDには氏名や学籍番号を使用せず、実験用の番号を割り当てます。倫理審査や研究室の運用規則がある場合は、それを優先してください。

### 2. VS Codeでローカルテストする

1. VS Codeでこのフォルダを開きます。
2. `index.html`をEdgeまたはChromeで開きます。
3. `TEST_CHECKLIST.md`の「VS Codeでのローカル確認」を実施します。

送信先URLが未設定の段階では、終了時に送信エラーが表示されます。これは正常です。CSVバックアップ機能は確認できます。

### 3. Googleスプレッドシートを準備する

1. Googleドライブで新しいスプレッドシートを作ります。
2. ファイル名を例として「配置問題_回答データ」にします。
3. メニューの「拡張機能」→「Apps Script」を開きます。
4. 初期コードを削除し、`google-apps-script/Code.gs`の内容を貼り付けて保存します。
5. 「デプロイ」→「新しいデプロイ」→種類「ウェブアプリ」を選びます。
6. 実行ユーザーを「自分」、アクセスできるユーザーを研究室の運用に合わせて設定します。GitHub Pagesから匿名で回答させる場合は「全員」が必要です。
7. デプロイし、表示された `/exec` で終わるウェブアプリURLをコピーします。
8. `config.js`の `endpointUrl` を、そのURLへ置き換えます。

### 4. Googleスプレッドシートへの保存を確認する

1. `index.html`を再度開き、10問すべて回答します。
2. 終了画面に「回答データを送信しました」と表示されることを確認します。
3. スプレッドシートに `responses` シートが作られ、10行追加されたことを確認します。
4. 回答、正誤、回答時間をCSVバックアップと照合します。

Apps Scriptを修正した場合は、デプロイの「管理」から新しいバージョンを反映してください。

### 5. GitHubへ公開する

1. GitHubで新しい公開リポジトリを作ります。例：`placement-web-test`
2. このフォルダ内のファイルを、リポジトリのルートへアップロードします。
3. リポジトリの「Settings」→「Pages」を開きます。
4. Sourceを「Deploy from a branch」、Branchを `main`、フォルダを `/ (root)` にして保存します。
5. 数分後に表示されるGitHub PagesのURLを開き、動作確認します。

注意：共有するURLはGitHubのソースコード画面ではなく、`https://ユーザー名.github.io/placement-web-test/` 形式のPages URLです。

### 6. QRコードを作成する

1. EdgeまたはChromeでGitHub Pagesの公開URLを開きます。
2. アドレスバー付近の共有機能、またはページ上の右クリックから「このページのQRコードを作成」を選びます。
3. QRコード画像を保存し、研究室の資料へ貼ります。
4. スマートフォンで読み取り、公開ページが開くことを確認します。

### 7. ミーティングで共有する前の最終確認

`TEST_CHECKLIST.md`を使い、PCとスマートフォンの両方で確認します。最初は研究室の1〜2名だけで送信し、スプレッドシートへ正しく保存されることを確認してから全員へ共有します。

### 8. 結果をもとに修正する

正答率と回答時間を問題ごとに集計し、`RESEARCH_PLAN.md`の判断基準に沿って難易度を調整します。コードを修正した場合はGitHubへ再度反映し、`config.js`の `testVersion` も更新します。
